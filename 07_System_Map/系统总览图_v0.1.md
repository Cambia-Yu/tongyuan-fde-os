# FDE OS 是什么？（30 秒）

**它是一套「企业 AI 项目的工作方法+操作手册」，不是软件应用，也不会自动运行任何项目。**

| 它是 | 它不是 |
|---|---|
| 判断规则（什么该做/该停） | 不是 AI 产品或业务系统 |
| 项目流程（十阶段+放行闸门） | 不是项目管理软件 |
| 角色责任（谁建议/谁确认/谁批） | 不是自动决策引擎 |
| 可填写的工具表（10 张） | 本地网页只是**阅读器**，不是产品本体 |

**它解决一个问题**：怎样把一个企业业务问题，一步步送到真实用户手里使用，并用**使用证据**决定停止、迭代还是扩大。

## 核心循环（白话版）

客户带着问题来 → 我们先取证（现状基线/优秀员工怎么干/人和系统怎么配合）→ 从证据构造方案（两条常用路线见下）→ 做出**可部署的业务切片**（不是 Demo）→ 交给真实用户使用 → 记录使用轨迹 → 凭证据决定停止/迭代/扩大 → 沉淀可复用能力 → 下一次更快。

**三条容易搞混的线**：「能演示」「有网址」「已上线」都**不等于**真实使用（用户拿系统结果完成了真事才算）；一次真实使用也**不等于**现场验证（要重复、有代表性的证据）。

## 方案构造的两条常用路线（汇合到「可部署切片」）
1. **评测驱动**：从失败案例反推——客户现在哪里最痛、AI 最窄能做到哪一步，先做最小可验证能力；
2. **能力驱动**：已有可复用的技能/工作流，经后端接口+交互入口封装成客户工具（先有问题证据+七项检查，防止「见技能就做产品」）。
两条路线都汇合到同一个检查点：这个切片能进真实业务流吗？谁来确认结果？出错怎么停？

## 流程与闸门（进阶）
十阶段（资格→问题→基线→轨迹→就绪→建造→评测→受控部署→运营→沉淀）×闸门（值不值得做→…→值得规模化）×使用状态 U1-U5 的完整对照见[链路对齐总表](../03_Delivery_Playbook/链路对齐总表_v0.1.md)。**流程是地图不是铁轨**——按证据跳段/并行/退回都合法，闸门管放行。
