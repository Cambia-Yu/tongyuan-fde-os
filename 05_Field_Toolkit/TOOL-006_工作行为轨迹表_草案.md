# TOOL-006｜工作行为轨迹表（Work Trace Sheet）草案 v0.2

## Purpose｜为什么存在
SOP 只说明组织**认为**该怎么工作；Agent 应该学的是表现优秀的人**实际**怎么工作。本表记录真实人员处理真实 Case 的行为序列——看了什么、做了什么、动作导致什么变化、什么信息改变判断、何时升级/求助——产出三样东西：Agent 工作流与 Skill 素材（业务规则候选）、〔TOOL-005〕的选例与差异分析输入、系统摩擦清单（流程重构/自动化候选，**不教给 Agent**）。

**核心纪律**：只记「观察到的行为」与「观察到的状态变化」，「事后推测的原因」单独标注且不得混入行为列。**不是所有动作都要学**：影子表格可能承载未成文的真实业务规则——「偏离系统」不等于「低效」。

## Entry Criteria｜进入条件
- 已锁定任务单元与 ≥1 名被观察的实操人员（优先熟练/公认优秀者，其次普通者作对照）；
- 已备好 **初始 discovery 最低样本：3-5 笔真实发生的 Case**（优先含 1 笔异常/模糊件，不摆拍示例件——注意：这只是起步数量，何时算够见 Exit）；
- 已取得人员知情同意与客户授权（录屏/拍照/日志涉及员工行为数据——隐私边界为公司规则待建项，观察前必须口头+书面双确认）；
- 观察者已读过 Case 背景材料，能区分业务术语。

## Actions｜怎么做
1. **完整演示一笔**：请人员按平时方式从头处理，**不打断、不建议**；先记事实动作，演示完再逐段追问（对接手册规范 §8.7 访谈法）。
2. **逐动作记录八要素**：动作 / 查看的材料或系统 / 当时的输入信息 / 判断或决策 / **耗时（可估）** / **动作结果·状态变化（state after：做完这步后，什么变了——单据状态、表格新增行、系统里的字段、口头结论）** / 是否求助或升级（向谁）/ 该动作是否触发返工或返航。
3. **追问「改变判断的时刻」**：哪个信息让你从 A 判断转向 B？——决策逻辑核心采集点，单独成行。
4. **三分类标注**（每个动作必标，混合可多选）：**业务规则候选**（该做，值得教）/ **系统摩擦**（仅为绕开工具缺陷，不该教）/ **混合待核**（拿不准，进 Bad Case Review 复核）。
5. **区分人员画像**：优秀者与普通者各观察至少 1 人，差异段落回填〔TOOL-005〕优秀差异摘录。
6. **饱和检查**：每完成一笔即问——本笔是否出现了**新的动作类型/新的分支/新的信息源**？连续多笔无新增即为轨迹饱和信号。

## Exit Criteria
- 轨迹开始**饱和**（新 Case 不再产生新动作类型/新分支）且**关键异常已覆盖**（不是固定笔数达标）；
- 每动作八要素齐全且三分类已标；
- 「改变判断时刻」≥1 段/人；
- 追问所得原因均标注「事后自述」；
- 摩擦清单与规则候选清单分列，未混写。

## Artifacts / Fields
| 字段 | 填写要求 |
|---|---|
| Case 编号 | 关联 TOOL-005 Case 池 |
| 人员画像 | 熟练/普通；岗位年限（脱敏） |
| 序号 | 行为顺序号 |
| 动作 | 观察到的动词（查看/计算/电话/粘贴…） |
| 材料/系统 | 打开了什么（单据/Excel/群聊/ERP 界面） |
| 关键输入 | 触发该动作的信息 |
| 判断/决策 | 当下的结论或选择；「改变判断时刻」加 ★ |
| 耗时 | 秒/分级估算即可，注明估或测 |
| **动作结果·状态变化** | 做完后什么变了（单据状态/表格/系统字段/口头结论） |
| 求助/升级 | 对象与原因 |
| 返工标记 | 该动作是否导致返工/返航 |
| 三分类 | 规则候选/系统摩擦/混合待核 |
| 事后自述 | 追问所得原因，单独列，不得并入行为列 |
| 观察反应性标记 | 本笔是否处于被观察初期/观察条件说明 |

## Hold 条件｜什么情况下停
- 客户或员工未授权记录 → 只做无记录参与式观察，产出降级为流程草图；
- 只能拿到 SOP/方案文档、无法观察真人 → **不构成 Work Trace**（方案设计链路≠行为轨迹）；
- 人员只肯演示「标准流程」不愿演示真实件 → 停，换人或换场景（摆拍轨迹无价值）；
- 三分类「混合待核」占比过半 → 说明观察者不懂业务，先补业务学习再继续。

## 附：观察反应性（霍桑效应）处置
不硬性废弃首日数据。处置规则：观察初期（首日或首批）收集的轨迹**标注「初期观察」**，与后续数据分开统计；是否采纳该批数据，取决于观察条件（单次在场 vs 长期在场、人员是否已习惯）与数据用途（流程发现可含初期数据；精细时长分布测量宜以适应后数据为主）。判断理由记录在案。
