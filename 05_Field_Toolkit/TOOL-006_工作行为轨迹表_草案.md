# TOOL-006｜工作行为轨迹表（Work Trace Sheet）草案

## Purpose｜为什么存在
SOP 只说明组织**认为**该怎么工作；Agent 应该学的是表现优秀的人**实际**怎么工作。本表记录真实人员处理真实 Case 的行为序列——看了什么、做了什么、什么信息改变了判断、何时升级/求助——产出三样东西：Agent 工作流与 Skill 的素材（业务规则候选）、〔TOOL-005〕的选例与差异分析输入、系统摩擦清单（流程重构/自动化候选，**不教给 Agent**）。

**核心纪律**：只记「观察到的行为」，「事后推测的原因」必须单独标注且不得混入行为列。**不是所有动作都要学**：影子表格可能承载未成文的真实业务规则——「偏离系统」不等于「低效」。

## Entry Criteria｜进入条件
- 已锁定任务单元与 ≥1 名被观察的实操人员（优先熟练/公认优秀者，其次普通者作对照）；
- 已备好 3-5 笔**真实发生**的 Case（优先含 1 笔异常/模糊件，不摆拍示例件）；
- 已取得人员知情同意与客户授权（录屏/拍照/日志涉及员工行为数据——隐私边界为公司规则待建项，观察前必须口头+书面双确认）；
- 观察者已读过 Case 背景材料，能区分业务术语。

## Actions｜怎么做
1. **完整演示一笔**：请人员按平时方式从头处理，**不打断、不建议**；先记事实动作，演示完再逐段追问（对接手册规范 §8.7 访谈法）。
2. **逐动作记录六要素**：动作 / 查看的材料或系统 / 当时的输入信息 / 判断或决策 / 耗时（可估）/ 是否求助或升级（向谁）。
3. **追问「改变判断的时刻」**：哪个信息让你从 A 判断转向 B？——这是决策逻辑的核心采集点，单独成行。
4. **三分类标注**（每个动作必标，混合可多选）：**业务规则候选**（该做，值得教）/ **系统摩擦**（仅为绕开工具缺陷，不该教）/ **混合待核**（拿不准，进 Bad Case Review 复核）。
5. **区分人员画像**：优秀者与普通者各观察至少 1 人，差异段落回填〔TOOL-005〕优秀差异摘录。
6. **首日只熟悉不计数据**：被观察者首日行为受观察影响大（霍桑效应），首日材料仅作背景。

## Exit Criteria
- ≥3 笔完整 Case 的行为序列，每动作六要素齐全且三分类已标；
- 「改变判断时刻」≥1 段/人；
- 追问得到的原因均已标注「事后自述」（区别于直接观察）；
- 摩擦清单与规则候选清单分列，未混写。

## Artifacts / Fields
| 字段 | 填写要求 |
|---|---|
| Case 编号 | 关联 TOOL-005 Case 池 |
| 人员画像 | 熟练/普通；岗位年限（脱敏） |
| 序号 | 行为顺序号 |
| 动作 | 观察到的动词（查看/计算/电话/粘贴…） |
| 材料/系统 | 打开了什么（单据/Excel/群聊/ERP 界面） |
| 关键输入 | 触发该动作的信息 |
| 判断/决策 | 当下的结论或选择；「改变判断时刻」加 ★ |
| 求助/升级 | 对象与原因 |
| 三分类 | 规则候选/系统摩擦/混合待核 |
| 事后自述 | 追问所得原因，单独列，不得并入行为列 |

## Hold 条件｜什么情况下停
- 客户或员工未授权记录 → 只做无记录参与式观察，产出降级为流程草图；
- 只能拿到 SOP/方案文档、无法观察真人 → **不构成 Work Trace**（方案设计链路≠行为轨迹）；
- 人员只肯演示「标准流程」不愿演示真实件 → 停，换人或换场景（摆拍轨迹无价值）；
- 三分类「混合待核」占比过半 → 说明观察者不懂业务，先补业务学习再继续。
