# TOOL-008｜评测集构建与回归表（Eval Suite Sheet）草案

> **白话**：系统做出来后怎么知道它「到底会不会、还会不会」？本表回答两件事——**能力评测集**（现在能做到什么，GATE-5 的达标依据）和**回归集**（以前会的有没有被改坏）。它和黄金集（业务上什么算对）是上下游：黄金集给「对错标准」，本表给「考试卷与成绩册」。

## Purpose
在既定任务、判据和环境下，回答「系统表现是否达到项目约定标准」（服务 GATE-5）；并保证版本演进不破坏已验证能力。**只管评测，不管生产风险**（那是 DEL-013/GATE-6 的事——评测通过≠生产风险可接受）。

## 四个对象先分清（不得混写）
| 对象 | 回答什么 | 来源 |
|---|---|---|
| 人工参照系 | AI 和什么人类表现比 | TOOL-005A |
| 黄金集 | 业务上什么算正确/优秀 | TOOL-005B（对错标准，本表的输入） |
| **能力评测集** | 当前系统还会不会、能做到什么 | 本表构建；初期低通过率，选系统挣扎的任务（爬坡对象） |
| **回归集** | 已会能力是否被新版本破坏 | 能力集「毕业」而来；应接近全过、持续运行捕捉漂移 |

## Entry Criteria
- 黄金集 v1 已冻结（TOOL-005B）；
- 任务定义与成功条件已由业务口径确认；
- 评分器选型已定（见字段）且模型评分器已有人工校准记录。

## Actions
1. **建能力集**：从黄金集+真实失败案例取例，**正反例平衡**（正常/异常/模糊/低频），每例登记来源与授权/脱敏状态、首次见到时间、使用过的系统版本、泄漏风险；
2. **多次试验**：每任务跑多 trial（模型输出不稳定，单次不算数）；
3. **评分与校准**：优先确定性评分器（快/客观/可复现）；必要时模型评分器（须与人工专家校准，允许回答「无法判定」）；人工评分用在刀刃上；
4. **错误分类**：每次失败归类（判据含糊/能力不足/数据问题/理解错误）——按 DEL-011 反馈路由分流；
5. **毕业机制**：能力集通过率持续走高→「毕业」为回归集条目，持续运行；
6. **版本与退役**：环境与模型/Skill 版本锁定记录；判据或业务事实纠错时**发布新版本并保留变更原因与历史版本**（旧答案不可静默改写，也不永久视为真值）；退役条目留档；
7. **生产案例防污染**：生产失败案例先进候选池（Issue #4 四步：识别→授权/脱敏→专家判定→版本化），不直接成为黄金答案；**同一案例不得既用于修方案又用于宣称效果**（归属三选一：能力集/回归集/独立复核集）。

## Exit Criteria
- 能力集+回归集各有版本号、构成清单、当前通过率与错误分类汇总；
- 项目阈值有批准记录（依据业务风险/错误严重度/人工基线/检测目标——**不设通用样本量、统一准确率或万能通过线**；Anthropic「20-50 条真实失败起步」仅作早期实践参照非 OS 硬阈值）；
- GATE-5 结论按放行六态出具。

## Artifacts / Fields（字段组）
| 字段组 | 内容 |
|---|---|
| 集合标识 | 类型（能力/回归）/版本/构成清单 |
| 案例登记 | 来源与授权脱敏/首次见到时间/历史使用版本/泄漏风险/归属（能力/回归/独立复核） |
| 任务定义 | 输入/成功条件/判定者与仲裁 |
| 评分器 | 类型选型理由/模型评分器人工校准记录/「无法判定」出口 |
| 运行 | trial 次数/环境与版本锁定/通过率 |
| 错误分类 | 分类与路由出口 |
| 变更 | 毕业记录/纠错新版本与原因/退役档案 |
| 阈值 | 项目约定值+批准记录（业务负责人+技术负责人） |

## Hold 条件
- 黄金集未冻结或判据含糊未修 → 不得出具 GATE-5 结论；
- 评分器未经校准 → 结果只作内部参考，不得用于放行；
- 离线分数不得替代真实使用结果（与生产监测并列，瑞士奶酪：任一层不兜底）；
- 同一案例被发现双用（修方案+宣称效果）→ 该案例从效果主张中剔除。
