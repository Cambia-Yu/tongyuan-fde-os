# TOOL-008｜评测集构建与回归表（Eval Suite Sheet）草案

> **白话**：系统做出来后怎么知道它「到底会不会、还会不会」？本表回答两件事——**能力评测集**（现在能做到什么，GATE-5 的达标依据）和**回归集**（以前会的有没有被改坏）。它和黄金集（业务上什么算对）是上下游：黄金集给「对错标准」，本表给「考试卷与成绩册」。

## Purpose
在既定任务、判据和环境下，回答「系统表现是否达到项目约定标准」（服务 GATE-5）；并保证版本演进不破坏已验证能力。**只管评测，不管生产风险**（那是 DEL-013/GATE-6 的事——评测通过≠生产风险可接受）。

## 四个对象先分清（不得混写）
| 对象 | 回答什么 | 来源 |
|---|---|---|
| 人工参照系 | AI 和什么人类表现比 | TOOL-005A |
| 黄金集 | 业务上什么算正确/优秀 | TOOL-005B——**仅专家判断类任务的输入**；客观 outcome 类任务用经确认的验证方式/参考解 |
| **能力评测集** | 当前系统还会不会、能做到什么 | 本表构建；初期低通过率，选系统挣扎的任务（爬坡对象） |
| **回归集** | 已会能力是否被新版本破坏 | 能力集毕业、已修复生产故障、历史人工检查、关键不变量（来源逐条登记）；应接近全过、持续运行捕捉漂移 |

## Entry Criteria
- 每项任务有**已确认的成功条件 + 可工作的参考解/验证方式**：可客观验证的结果类任务可由数据库最终状态、规则检查、单元测试或审批结果直接判定，**不强制要求文本式黄金答案**；需要业务专家判断的任务才要求 TOOL-005B 黄金集冻结；
- 任务定义与成功条件已由业务口径确认；
- 评分器选型已定（见字段）且模型评分器已有人工校准记录。

## Actions
1. **建能力集**：从黄金集+真实失败案例取例，覆盖**行为应发生/不应发生两向**（正常/异常/模糊/低频），并**记录与目标分布的差异**（不默认等量平衡，也不拿生产分布直接替代高风险切片）；每例登记来源与授权/脱敏状态、首次见到时间、历史使用版本、**泄漏风险（分列：①评测集污染=案例是否曾暴露给开发/训练流程；②内容外泄=客户数据经日志/模型外流风险）**；
2. **试验策略**：按系统随机性、风险与检测目标**预先声明** trial 次数与聚合指标——确定性环节可单次；随机性环节须多 trial，并登记聚合指标选型（pass@k / 一致成功类 / 任务成功率）及理由，**不能只记次数**；
3. **评分与校准**：优先确定性评分器（快/客观/可复现）；必要时模型评分器（须与人工专家校准，允许回答「无法判定」）；人工评分用在刀刃上；**「无法判定」计为不通过（保守处理）且弃权率单独列报**，弃权率上限进入项目阈值三栏批准（候选设计）；
4. **错误分类**：每次失败归类（判据含糊/能力不足/数据问题/理解错误）——按 DEL-011 反馈路由分流；
5. **毕业与回归集来源**：能力集通过率持续走高→「毕业」迁入回归集（**记录迁移日期、触发版本、用途变化**）；回归集亦可来自已修复生产故障、历史人工检查、关键不变量——来源逐条登记；
6. **版本与退役**：环境与模型/Skill 版本锁定记录；判据或业务事实纠错时**发布新版本并保留变更原因与历史版本**（旧答案不可静默改写，也不永久视为真值）；退役条目留档；
7. **防污染（时序与用途制）**：生产失败案例先进候选池（四步：识别→授权/脱敏→专家判定→版本化），不直接成为黄金答案。真正禁止的是**同一版本、同一次效果主张中用已参与开发/修复的案例冒充独立效果证据**——不是禁止案例随时间从能力集迁入回归集。规则：①用于修方案/调提示/调评分器的案例，不得进入**同版本的独立效果估计**；②独立复核集在结论冻结前**不可用于开发**，发生泄漏→降级为能力/回归用途并更换独立复核案例；③每例登记「开发是否见过 / 首次用于哪一版本 / 当前用途 / 历史用途」。

## Exit Criteria
- 能力集+回归集各有版本号、构成清单、当前通过率与错误分类汇总（**首版无历史回归基线时**：可建关键不变量回归集，或明确登记「尚无回归基线」的证据上限与对应 Hold 条件——不形成「必须先有回归集才能评」的循环）；
- 项目阈值有批准记录（依据业务风险/错误严重度/人工基线/检测目标——**不设通用样本量、统一准确率或万能通过线**；Anthropic「20-50 条真实失败起步」仅作早期实践参照——**引用时禁止写成占位默认值，任何数字进入字段前须过三栏批准**）；
- GATE-5 结论按放行六态出具——**六态=通过／有条件通过／退回补充／缩小范围／暂停／终止**（源自手册规范 §8.10）；**结论签发**＝三栏批准记录中的正式批准方（有权人），非填表人（**批准三栏分立**：业务口径与错误严重度=客户业务责任方确认；评测设计充分性=技术方复核；GATE-5 正式批准=按现有授权指定的有权人——模板不自动把参与者写成共同批准人，授权不明即 Unknown/Hold）。

## Artifacts / Fields（字段组）
| 字段组 | 内容 |
|---|---|
| 集合标识 | 类型（能力/回归）/版本/构成清单 |
| 案例登记 | 来源与授权脱敏/首次见到时间/泄漏风险/**开发是否见过/首次用于哪一版本/当前用途/历史用途**（迁移记日期+触发版本） |
| 任务定义 | 输入/成功条件/判定者与仲裁 |
| 评分器 | 类型选型理由/模型评分器人工校准记录/「无法判定」出口 |
| 运行 | trial 次数/环境与版本锁定/通过率 |
| 错误分类 | 分类与路由出口 |
| 变更 | 毕业记录/纠错新版本与原因/退役档案 |
| 阈值 | 项目约定值+**三栏批准记录**（业务口径确认方/技术充分性复核方/GATE-5 正式批准方） |

## Hold 条件
- **所需判据未冻结／验证方式不可工作／（专家判断类任务）黄金集未冻结**或判据含糊未修 → 不得出具 GATE-5 结论（客观验证类任务不被黄金集缺位阻断）；
- 评分器未经校准 → 结果只作内部参考，不得用于放行；
- 离线分数不得替代真实使用结果（与生产监测并列，瑞士奶酪：任一层不兜底）；
- 同一案例被发现双用（修方案+宣称效果）→ 该案例从效果主张中剔除。


## 附｜贯穿案例最小填写示例（网络货运支付前审核；**历史材料纸面推演，不是现场证据**）
任务：判定一笔真实历史订单（证件/轨迹/凭证齐全性）是否可放行付款——成功条件=「可客观验证」类（最终状态=系统审核结论与人工复核结论比对），无需文本黄金答案；错误严重度=错放行>错拦截（由客户业务责任方确认）。
- **行业读者提供/确认**：任务定义、两类错误严重度、15 条规则的业务口径（未取得=Hold）、独立复核集候选订单（确认未被开发见过）；
- **工程读者实现/复核**：trial 策略（审核判定含随机环节→多 trial+任务成功率）、评分器选型（结果比对=确定性评分器）、环境与版本锁定、泄漏防护；
- **共同产物**：能力集 v1（两向覆盖+分布差异记录）→ GATE-5 结论（六态）；
- **谁不能替谁**：工程读者不得定义业务口径与严重度；行业读者不得批准技术充分性；正式批准=有权人；
- **何时必须停**：判据含糊未修/评分器未校准/独立复核集发生泄漏→Hold。
（B 包 TOOL-009 示例从本例 GATE-5 通过后继续。）
