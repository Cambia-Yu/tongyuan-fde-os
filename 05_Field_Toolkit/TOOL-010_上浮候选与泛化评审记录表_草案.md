# TOOL-010｜上浮候选与泛化评审记录表草案

> **白话**：前线做出来的东西想收进公司共享能力层，这张表记录「评审时看了什么、凭什么放行或退回」——它不登记资产本身（那是资产卡的事），只留评审的决定与理由。

## Purpose
承载三道判断（触发评审/公共层准入/成熟状态）的完整留痕；产出五方权责记录；给阶段 09 提供可退出的完成标准（**决定+理由留痕即可退出，准入与否不卡阶段**）。

## Entry Criteria
- 出现任一触发信号（同客户二次使用/跨项目结构相似/同一失败模式重复）；
- 候选的适用范围标签已初判（四类之一）；
- 原项目至少完成阶段 05（有可追溯的实现与结果）。

## Actions
1. **登记候选**：描述+触发信号+范围标签+来源项目；
2. **第一道（触发评审）**：结论三选（进入评审/继续观察/不进入）+理由；
3. **拆分测试**：公共不变量 vs 客户覆盖层清单+反例检验（能力沉淀 §6-§7 方法；关键不变量不成立→拆分或保留本地）；
4. **四类防污染逐类审查**（能力沉淀 §3 表：字段/证据/隔离/确认人/Hold/最小条件）；
5. **第二道（准入）**：结论六选（准入/有条件准入/退回补充/保留项目本地/Hold/拒绝）+理由；准入→另按 24 字段填资产卡（受控库登记访问位置）；
6. **第三道（成熟状态）**：结论六选（维持/升级/降级/暂停/替代/归档）+证据引用（上限规则见能力沉淀 §1）；
7. **效果登记启动**（如准入）：六项效果信号自首个复用事件起记。

## Exit Criteria
- 三道判断各有结论+理由+决策人；
- 五方权责分列完整（未知→Hold 留痕）；
- 拆分测试记录在案（含最初假设与是否被推翻）。

## Artifacts / Fields
| 字段 | 填写要求 |
|---|---|
| 候选编号/描述/来源项目 | 可追溯 |
| 触发信号 | 三类之一+证据 |
| 适用范围标签 | 四类之一（可随评审改判） |
| 第一道结论 | 进入评审/继续观察/不进入+理由 |
| 公共不变量清单 | 任务目的/输入输出契约/控制点/评测方式/失败分类 |
| 客户覆盖层清单 | 字段/口径/阈值/例外/权限/连接器/基础设施/运维 |
| 反例检验 | 何种差异证明非同一能力；是否触发拆分 |
| 四类防污染审查 | 每类：判定/证据/隔离/确认人/Hold |
| 第二道结论 | 六选+理由；准入→资产卡编号+受控库位置 |
| 第三道结论 | 六选+证据上限核对 |
| 五方权责 | 授权/业务确认/技术复核/合并批准/新客户部署（谁提供证据/确认/复核/批准/权限依据；未知=Hold） |
| 效果登记 | 六项信号（自首个复用起记） |

## Hold 条件
- 任一类防污染证据缺失或确认人未知 → Hold；
- 拆分测试未做即申请准入 → 退回；
- 权限依据文件缺失（口头授权不算）→ Hold；
- 范围标签为「同客户可复用」却按「跨客户泛化」申请 → 退回重标。
