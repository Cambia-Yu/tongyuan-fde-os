# TOOL-010｜上浮候选与泛化评审记录表草案 v0.3

> **白话**：前线做出来的东西想收进公司共享能力层，这张表按**条件式分支**记录评审——走到哪道判断、为什么停在那里、下次什么条件继续。它不登记资产本身（那是 24 字段资产卡的事），只留决定与理由。

## 用途（Purpose）
承载三道判断的分支化留痕；产出五方权责记录；阶段 09 的完成标准=**本次适用的判断分支**完成决定与理由留痕（不要求三道全做）。

## 进入条件（Entry Criteria）——双入口
**入口 A｜新候选**：
- 出现任一触发信号（同客户二次使用/跨项目结构相似/同一失败模式重复）；范围标签已初判；**来源可以是任一阶段的产物**（失败模式/数据接入/口径冲突/权限问题可在阶段 01-04 出现）：须有可追溯的事实/材料、来源项目与 Case、观察与推断分离——证据不足只影响结论与成熟上限，不阻断登记。**可运行能力类候选**才要求实现/结果证据；**失败模式类不要求先有成功实现**。

**入口 B｜已存在资产复审**：
- 资产 ID、当前状态、**复审触发原因与证据**（如：新复用事件/新失败/新环境适配/定期复查）——**不要求新候选触发信号，不强制第一、二道与拆分测试**，未适用项写 N/A。

## 操作步骤（Actions，条件式）
1. 【入口 A】登记候选（第一道观察允许信息不全）；
2. 【入口 A】**第一道（触发评审）**：「进入评审」→第 3 步；「继续观察/不进入」→**记理由与复查条件后完成**；
3. 【入口 A】拆分测试（不变量 vs 覆盖层+反例；可拆出多候选各自走分支）；
4. 【入口 A】四类防污染逐类审查（六要素记录位见字段表）；
5. 【入口 A】**第二道（公共层准入）**：准入→第 6 步；「有条件准入/退回补充/保留项目本地/Hold/拒绝」→**记结论、理由、补证或保留位置后完成**；
6. 【入口 A·准入后】创建/关联资产卡+登记初始状态四项（建议状态/证据上限核对/批准状态/差异理由）；
7. 【入口 A 或 B】**第三道（成熟状态）**：结论六选（维持/升级/降级/暂停/替代/归档）+证据引用；入口 B 直达本步。

## 完成与放行条件（Exit Criteria，按分支）
- **分支「第一道继续观察/不进入」**：第一道决定+理由+复查条件即完成；拆分测试=**N/A（未进入第二道）**；五方权责=N/A；
- **分支「第二道未准入（含 Hold/拒绝/保留本地/退回）」**：第二道决定+理由+补证/保留位置即完成；初始状态与资产卡=N/A（未准入）；
- **分支「准入」**：四类审查+五方（适用项）+初始状态四项+资产卡关联；
- **入口 B（独立成熟复审）**：复审触发原因+证据+第三道结论即完成；拆分测试/第一、二道=N/A；
- 五方权责与拆分测试**只在对应分支适用时要求**，不作全分支统一必填。

## 阶段产物与字段（Artifacts / Fields）
| 字段 | 填写要求 |
|---|---|
| 入口类型 | A 新候选 / B 已存在资产复审 |
| 候选/资产标识 | A=候选编号+描述+来源项目与 Case+来源阶段；B=资产 ID+当前状态+复审触发原因与证据 |
| 触发信号（仅 A） | 三类之一+证据（允许不全） |
| 适用范围标签（仅 A） | 四类之一（可改判） |
| 第一道结论（仅 A） | 进入评审/继续观察/不进入+理由+复查条件 |
| 拆分测试（仅 A 且进入评审后） | 不变量/覆盖层/反例/是否拆分及候选清单 |
| 四类防污染审查（仅 A 且走到第二道） | 每类六要素：判定字段/证据来源/隔离方式/确认方/该类 Hold/最小准入条件 |
| 第二道结论（仅 A 且走到） | 六选+理由；准入→资产卡编号+受控库位置 |
| 初始状态四项（仅准入后） | 建议状态/证据上限核对/批准状态/差异理由 |
| 第三道结论（A 准入后或 B） | 六选+证据引用；B 登记启动原因 |
| 五方权责（按适用分支） | 授权/业务确认/技术复核/合并批准/新客户部署（无目标部署=N/A—尚无目标部署，不据此 Hold）；谁提供证据/确认/复核/批准/权限依据 |
| 效果登记 | 六项信号（Unknown——自首个复用事件起采，登记启动时点） |

## 暂停与阻断条件（Hold）
- **当前适用且准入必需**的证据缺失或确认方 Unknown→Hold（原客户权利与数据授权方/业务语义确认方/技术充分性复核方/公共层合并批准方四方；**不适用项如新客户部署批准方=N/A 不触发 Hold**）；
- Hold 须列：所缺证据/补证负责人与来源/复审触发条件/复审时点；
- Unknown/N/A/待未来事件触发三分；拆分测试未做即申请准入→退回；「同客户可复用」按「跨客户泛化」申请→退回重标。

## 附｜三条分支实际填表示例（纸面推演，未虚构授权与效果数据）
**示例 1｜第一道「继续观察」**（结算数字一致性判定资产）：入口 A；触发=跨项目结构相似；第一道=**继续观察**（范围标签=同客户可复用，无跨客户证据；判定对象与错误方向同货运审核相反）+复查条件（出现第三个同类场景时重评）→**完成**；拆分测试=N/A（未进入第二道）；五方=N/A。
**示例 2｜第二道 Hold**（多源证据审核方法骨架）：入口 A；第一道=进入评审；拆分测试通过（不变量成立）；四类审查：**权利类证据 Unknown（两客户案例授权未确认）→第二道结论=Hold**；所缺证据=两客户书面授权；补证负责人=业务问题负责人（候选）；复审触发=授权取得或任一客户书面拒绝（拒绝则改「保留项目本地」）；复审时点=授权文件到达后三个工作日内；初始状态四项=建议状态**内部演练**/证据上限核对**内部演练（仅纸面推演）**/批准状态=**N/A—尚未准入**/差异理由=无；效果六项=Unknown（未准入未复用，不启动）。
**示例 3｜入口 B 独立成熟复审**（已有资产 A-2026-03「文档解析连接器」，当前状态=单项验证）：入口 B；复审触发原因=新复用事件（第二个项目调用 v1.2）+新失败一例（加密 PDF 场景）；第三道=**维持单项验证**（新复用发生在同一受控环境，未构成「不同条件」；新失败已登记失败模式并回影响「不适用场景」字段）+理由；拆分测试/第一道/第二道=**N/A（已存在资产复审）**；效果登记：复用事件与资产版本已记，其余五项 Unknown。
