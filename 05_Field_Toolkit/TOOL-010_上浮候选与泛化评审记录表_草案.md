# TOOL-010｜上浮候选与泛化评审记录表草案 v0.2

> **白话**：前线做出来的东西想收进公司共享能力层，这张表按**条件式分支**记录评审——走到哪道判断、为什么停在那里、下次什么条件继续。它不登记资产本身（那是 24 字段资产卡的事），只留决定与理由。

## Purpose
承载三道判断的分支化留痕；产出五方权责记录；阶段 09 的完成标准=**本次适用的判断分支**完成决定与理由留痕（不要求三道全做）。

## Entry Criteria
- 出现任一触发信号（同客户二次使用/跨项目结构相似/同一失败模式重复）；
- 候选适用范围标签已初判（四类之一）；
- **来源可以是任一阶段的产物**（失败模式、数据接入、业务口径冲突、权限问题可能在阶段 01-04 就出现）：须有可追溯的事实/材料、来源项目与 Case、观察与推断分离——证据不足只影响评审结论与成熟上限，不阻断登记。**可运行能力类候选**才要求对应实现/结果证据；**失败模式类不要求先有成功实现**。

## Actions（条件式分支）
1. **登记候选**（描述+触发信号+范围标签+来源）——第一道观察**允许信息不全**；
2. **第一道（触发评审）**：结论三选——「进入评审」→继续第 3 步；「继续观察/不进入」→**记录理由与下次复查条件后即可 Exit**；
3. **拆分测试**：公共不变量 vs 客户覆盖层+反例检验（可能拆出多个候选，各自独立走后续分支）；
4. **四类防污染逐类审查**（每类六要素记录位见 Fields）；
5. **第二道（公共层准入）**：结论六选——准入→第 6 步；「有条件准入/退回补充/保留项目本地/Hold/拒绝」→**记录结论、理由、补证或保留位置后即可 Exit**；
6. **准入后**：创建/关联 24 字段资产卡+登记**初始状态**（按证据上限：建议状态/证据上限核对/批准状态/差异理由四项）；
7. **第三道（成熟状态复审）**：结论六选（维持/升级/降级/暂停/替代/归档）——**可针对已存在资产独立启动**，不必从新候选触发。

## Exit Criteria
- **本次适用的判断分支**有结论+理由+决策人（未走到的分支标「不适用——第 X 道结论为 Y」）；
- 五方权责按适用性分列完整；
- 拆分测试记录在案（含最初假设与是否被推翻）。

## Artifacts / Fields
| 字段 | 填写要求 |
|---|---|
| 候选编号/描述/来源项目与 Case/来源阶段 | 可追溯 |
| 触发信号 | 三类之一+证据（第一道允许不全） |
| 适用范围标签 | 四类之一（可随评审改判） |
| 第一道结论 | 进入评审/继续观察/不进入+理由+复查条件 |
| 拆分测试 | 不变量清单/覆盖层清单/反例/是否拆分及候选清单 |
| 防污染·权利合同 IP | 判定字段/证据来源（合同页、许可清单）/隔离方式/确认方/该类 Hold（如书面权利缺失）/最小准入条件 |
| 防污染·数据隐私衍生物 | 同上六要素（证据来源=脱敏审查记录等） |
| 防污染·业务语义 | 同上六要素（证据来源=口径文档、TOOL-005 分歧记录等） |
| 防污染·技术与运行耦合 | 同上六要素（证据来源=依赖清单、运行约束文档等） |
| 第二道结论 | 六选+理由；准入→资产卡编号+受控库位置 |
| 初始状态四项 | 建议状态/证据上限核对/批准状态/差异理由 |
| 第三道结论（如适用） | 六选+证据引用；独立复审登记启动原因 |
| 五方权责 | 授权/业务确认/技术复核/合并批准/新客户部署（无目标部署时=N/A—尚无目标部署，不据此 Hold）；谁提供证据/确认/复核/批准/权限依据 |
| 效果登记 | 六项信号（Unknown——自首个复用事件起采，登记启动时点） |

## Hold 条件（按适用性分层）
- **当前准入必需四方缺失→Hold**：原客户权利与数据授权方/业务语义确认方/技术充分性复核方/公共层合并批准方——任一未知即 Hold；
- **新客户部署批准方**：仅当发生具体新客户部署时必需；此前记 `N/A—尚无目标部署`，**不得据此 Hold 资产准入**；
- **Unknown / N/A / 待未来事件触发三者分开**：Unknown=应知而未知（Hold 候选）；N/A=结构上不适用；待触发=条件未到（登记触发条件）；
- 拆分测试未做即申请准入 → 退回；范围标签「同客户可复用」按「跨客户泛化」申请 → 退回重标。

## 附｜最小填表示例（网络货运×结算协同拆分测试产出，纸面推演）
- **触发**：跨项目结构相似（两案均「多源证据+规则核验+人工放行」）；拆分测试推翻初判「同一资产」→ 产出 **3 个候选**：
- **候选 1（方法骨架：多源证据审核工作流+评测方法论+失败分类）**：第一道=进入评审（不变量成立）；第二道=**有条件准入**——权利类证据 Unknown（两客户案例授权未确认）→ 记录 Hold 项与补证条件；初始状态建议=**内部演练**（仅纸面推演，未达单项验证）；新客户部署批准方=**N/A—尚无目标部署**；效果六项=Unknown（自首个复用事件起采）；
- **候选 2/3（两案各自业务资产：货运单据真实性判定 / 结算数字一致性判定）**：第一道=**继续观察**（范围标签=同客户可复用，无跨客户证据）——记录理由（判定对象与错误方向相反、输入形态与控制点不同）与复查条件（出现第三个同类场景时重评）后 Exit，**不进入第二道**；
- 全程未虚构授权与效果数据。
