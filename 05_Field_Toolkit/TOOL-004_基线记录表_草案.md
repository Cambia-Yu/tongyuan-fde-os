# TOOL-004｜基线记录表（Baseline Sheet）草案 v0.2

## Purpose｜为什么存在
没有基线，一切「提升 X%」都无法验证，只能事后发明指标（企业常见失败模式）。本表在 AI 介入**之前**先写清项目要改变的**核心业务指标**，再记录「这项工作现在实际做到什么水平」，服务三处：GATE-2 放行证据、MVP 价值对照（DEL-005 指标纪律）、合同/官网效果表述边界（COM-007）。

## Entry Criteria｜进入条件
- 已有明确任务单元（L2 准入通过，〔作业-准入-02〕在案）；
- 已取得可访问的数据来源或可观察的实际操作人员（至少 1 名）；
- 客户已书面同意提供统计所需数据或允许现场测量（口头不算）。

## Actions｜怎么做
1. **先定核心业务指标（Primary Business Outcome）**：项目真正要改变的业务结果是什么？指标公式（分子/分母）、统计单元（单据/案件/客户/天）由业务负责人确认——先有它，再决定需要哪些辅助基线（OpenAI 官方 eval 方法：从业务目的和最重要的 outcome 出发，而非固定指标清单）。
2. **定口径**：填「统计范围/时间窗口/样本来源/含排除项」，口径未定不得填数。
3. **选维度（默认检查框架，按需取舍）**：成本（人日/单价）、时长、质量（错误率/异常率分桶）、量（总量/人均）——四项是候选清单不是必测清单；**时长统计量按分布与业务问题选择**（成本核算可用均值，长尾延迟场景宜报中位数/P90，说明选择理由）。
4. **核代表性**：检查季节性、Case mix（正常/异常/模糊构成）、样本结构是否覆盖典型波动；窗口长度是设计建议（覆盖典型波动为宜），不设跨场景硬阈值——窗口不足时标注「初步值+局限」。
5. **交叉验证**：系统日志口径与操作人口述对不上时，以可追溯来源为准并记录差值。
6. **锁定**：基线确认后由业务负责人签字，写入 GATE-2 证据包；修正须新开一行并注明原因。

## Exit Criteria｜做到什么程度算完成
- 核心业务指标（公式+统计单元）已确认；
- 所选维度全部为「实测值」或明确标注「无法测量+原因+替代口径」；
- 每个数字有来源；代表性局限已注明；
- 业务负责人签字确认口径与数值。

## Artifacts / Fields｜留什么
| 字段 | 填写要求 |
|---|---|
| 任务单元名称/编号 | 与准入记录一致 |
| **核心业务指标** | 业务结果、指标公式（分子/分母）、统计单元 |
| 统计范围 | 哪个岗位/哪类单据/哪个环节 |
| 时间窗口 | 起止日期；是否覆盖典型波动/季节性 |
| 样本来源 | 系统名/表/导出方式或观察对象（脱敏） |
| Case mix | 正常/异常/模糊/低频构成比 |
| 排除项 | 明确不计入的情形（如退回件、系统故障期） |
| 成本基线（如适用） | 人日×单价；口径注明 |
| 时长基线（如适用） | 所选统计量+理由+样本量 n |
| 质量基线（如适用） | 错误率/异常率+分桶口径 |
| 量基线（如适用） | 总量、人均、峰值日 |
| 代表性局限 | 季节性/样本结构/窗口不足等，如实标注 |
| 口径争议记录 | 谁说的、差异、裁决人与依据 |
| 确认 | 业务负责人/日期/签字 |

## Hold 条件｜什么情况下停
- 只有单次/单例记录（如「上次那笔花了两天」）→ **不构成基线**，不得填入实测值；
- 核心业务指标未确认 → 不得进入任何效果测算与承诺；
- 数据只能口述取得 → 停在 L1，返回〔作业-准入-01〕补证据；
- 口径冲突未裁决 → 可以继续测量，但不得进入评测与 ROI 计算（R-C04）。
