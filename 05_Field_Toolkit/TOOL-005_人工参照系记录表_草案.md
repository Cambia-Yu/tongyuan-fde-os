# TOOL-005｜人工参照系记录表（Human Benchmark / Golden Case Sheet）草案

## Purpose｜为什么存在
Eval 需要标准答案，但**「最厉害员工的做法」不能直接当 Ground Truth**：单人判断无一致性可测，且优秀者的隐性判断只有通过多案例、多标注者才能显性化。本表把「合格/优秀人员在这类 Case 上能做到什么程度、好在哪里」建成分歧可控的参照系，直接产出 Eval 黄金集底稿（阶段 06）与 Agent 学习样本（阶段 03 的下游）。

## Entry Criteria｜进入条件
- 已有真实 Case 池（正常/异常/模糊/低频四类，来自〔作业-准入-01〕真实事项与历史样本）；
- 已有成文判定规则（如 15 条审核规则）或至少 2 名可参与的在岗人员（1 名无法算参照系）；
- 判定输出的「结果口径」已由业务负责人确认。

## Actions｜怎么做
1. **选例**：从真实 Case 池抽 10-30 例，覆盖四类分布（小而多样优于大而同质）。
2. **独立判定**：≥2 名人员**分别独立**对同一批 Case 给出判定+理由，互不通气。
3. **算分歧**：记录一致率；有条件时用机会校正指标（κ）；**分歧不是坏事，是诊断信号**——逐条归因：判据含糊 / 信息不足 / 个人风格 / 确有争议。
4. **仲裁**：僵持分歧交第三人（主管/规则 owner）裁决，裁决理由入表——裁决本身往往就是业务规则的显性化。
5. **分级**：每例标注「合格线答案 / 优秀答案 / 争议答案」；优秀者与合格者的差异段落单独摘出（这是 Agent 要学的部分）。
6. **冻结成集**：形成黄金集 v1（含答案、理由、分歧记录、裁决），版本化；后续 Bad Case 只增例不改旧答案。

## Exit Criteria
- 每例有 ≥2 个独立判定 + 分歧处理结果；
- 判据含糊项已回流为口径问题清单（交〔作业-准入-01〕口径争议记录）；
- 业务负责人确认黄金集 v1 可用于评测。

## Artifacts / Fields
| 字段 | 填写要求 |
|---|---|
| Case 编号/类型 | 正常/异常/模糊/低频 |
| Case 输入快照 | 脱敏材料（单据/截图/记录编号） |
| 判定者 A / 判定者 B | 各自结论+理由+关键依据（引规则条目） |
| 一致性 | 一致/不一致；一致率汇总 |
| 分歧归因 | 判据含糊/信息不足/个人风格/真争议 |
| 仲裁 | 裁决人/结论/理由/日期 |
| 等级 | 合格线/优秀/争议（争议例不入黄金集正文，入附录） |
| 优秀差异摘录 | 优秀者多做/先看/追问了什么 |
| 状态 | 草稿→试标→冻结 vN |

## Hold 条件
- 判定规则未成文且只有 1 名可参与人员 → 停，返回补规则/补人；
- 标注者未经过至少一轮试标校准 → 不得冻结版本；
- 分歧率过高（多数例不一致）→ 先修判据再标注，不硬凑答案；
- 优秀员工「做法」未经其本人确认理解 → 不得写入 Agent 学习样本（防误读隐性判断）。
