# TOOL-005｜人工参照系与黄金集记录表草案 v0.2

本表回答**两个不同的问题**，故拆为两个 section（同一文件仅为最小侵入）：

> **A｜人工参照系（Human Benchmark）**：在同类代表性 Case、可比条件下，人实际能做到什么水平——回答「**AI 应该和什么人类表现比较**」。
> **B｜黄金集（Golden Set）**：什么答案/行为被业务认为是正确或优秀的权威参照——回答「**怎么判 AI 对不对**」。

两者不可互替：METR 的人类基线是让真人做同任务测成功率与完成时间（评分标准另立）；OpenAI 定义的 golden set 是「最熟练专家对 great 判断的活的权威参照」。Eval 需要 B 判对错，ROI 与灰度对照需要 A 定「和谁比、比什么」。

---

## Section A｜人工参照系（Human Benchmark）

### Purpose
为 AI 效果对照选定**人类表现锚点**：不同水平的人（典型/合格/优秀——分层按场景定义，不预设万能分位）在同一任务上实际做到的结果质量、时长、成本、升级求助率。

### Entry Criteria
- 已有真实 Case 池（正常/异常/模糊/低频）；
- ≥2 名不同水平在岗人员可参与（同一人无法构成参照系分布）；
- 条件可比性已确认（同工具、同权限、同数据环境——不可比须注明）。

### Actions
1. **定分层**：按场景定义典型/合格/优秀（例：工龄、绩效、主管提名——写明依据），每层 ≥1 人。
2. **同条件实测**：每人对同一批 Case（10-30 例）实际完成，记录：结果质量（按业务口径）、成功/返工率、处理时长分布、投入工作量/成本、升级或求助次数。
3. **选对标层**：明确本项目 AI 首期对标哪一层（通常合格线，战略项目对标优秀层）——写入 MVP 验收前提。
4. **记可比条件**：工具版本、权限、辅助资源（是否允许查知识库/问同事）——这些改变会作废对比。

### Exit Criteria
- 每层至少 1 人完成同批 Case 实测；
- 对标层已选定并经业务负责人确认；
- 可比条件记录在案。

### Fields
| 字段 | 填写要求 |
|---|---|
| Case 批次编号 | 与 B 节共用 Case 池 |
| 人员层（典型/合格/优秀） | 分层依据 |
| 结果质量 | 按业务口径（如一次通过率/客诉率） |
| 成功率/返工率 | 分子分母口径 |
| 处理时长 | 分布+统计量+理由（同 TOOL-004 原则） |
| 工作量/成本 | 人时/人日×单价 |
| 升级/求助 | 次数与去向 |
| 可比条件 | 工具/权限/辅助资源 |
| 对标层决定 | 层+理由+业务负责人确认 |

### Hold 条件
- 只有 1 名人员可用 → 无法构成参照系，退化为单人样例并标注；
- 条件不可比（工具/权限差异大）→ 数据不用于 AI 对照，只作流程参考。

## Section B｜黄金集（Golden Set）构建

### Purpose
把「正确/优秀」的判定标准显性化、版本化，产出 Eval 的 Ground Truth 底稿（阶段 06 输入）。**「最厉害员工的做法」不能直接当答案**：单人判断无一致性可测；优秀者的隐性判断需多案例多标注者才能显性化。

### Entry Criteria
- 判定规则已成文（如 15 条审核规则）或至少 2 名可参与判定的在岗人员；
- Case 池与 A 节同源。

### Actions
1. **选例**：10-30 例，覆盖四类分布（小而多样优于大而同质）。
2. **独立判定**：≥2 人分别独立给出判定+理由（可借用 A 节实测记录，但判定必须独立成行）。
3. **算分歧**：输出可**离散判定**且样本/标注设计适用时，用机会校正指标（κ 类）；其他场景（开放式、专家单点判断）改用分歧清单+逐条归因，**不强行套 κ**。**IAA≥0.8 是部分来源的行业参考值，不是本 OS 硬规则**。分歧是诊断信号：判据含糊/信息不足/个人风格/真争议。
4. **仲裁**：僵持分歧交第三人裁决，裁决理由入表——裁决本身常是业务规则显性化。
5. **分级冻结**：每例标「合格线答案/优秀答案/争议答案」（争议例入附录）；版本化；**冻结版本不可静默改写——业务事实或判据纠错时发布新版本并保留变更原因与历史版本**（旧答案不永久视为真值；2026-08-18 按 Issue #5 边界 3 校准，原「只增例不改旧答案」表述废止）。

### Exit Criteria
- 每例 ≥2 独立判定+分歧处理结果；
- 判据含糊项回流口径问题清单；
- 业务负责人确认黄金集 v1 可用于评测。

### Fields
| 字段 | 填写要求 |
|---|---|
| Case 编号/类型 | 与 A 节共用 |
| Case 输入快照 | 脱敏材料 |
| 判定者 A / B | 结论+理由+依据规则条目 |
| 分歧处理 | 一致/归因/仲裁（人/结论/理由/日期） |
| 一致性指标 | 离散场景用 κ；其他场景注明「分歧清单法」 |
| 等级 | 合格线/优秀/争议 |
| 优秀差异摘录 | 优秀者多做/先看/追问了什么（回填 Work Trace） |
| 状态 | 草稿→试标→冻结 vN |

### Hold 条件
- 判定规则未成文且仅 1 人可判定 → 停，返回补规则/补人；
- 标注者未经过至少一轮试标校准 → 不得冻结版本；
- 分歧率过高 → 先修判据再标注，不硬凑答案；
- 优秀员工做法未经其本人确认理解 → 不得写入 Agent 学习样本。
