# TOOL-001｜客户初步调查表（仓库版）

**用途**：把宽泛需求转成可取证据、可判断价值的候选任务。**进入**：客户问题首次进入评估。**主持**：FDE 职能；**参与**：业务负责人+实际操作人员（+风险/财务如涉）。

## A 项目基本信息
| 字段 | 填写 |
|---|---|
| 客户/业务单位｜调查日期｜主持｜参与人及角色 | |
| 客户问题原文+来源（会议/邮件/需求文件） | |
| 期望变化｜期望时间｜是否已被要求报价/承诺指标 | |

## B 近期真实业务事项（14 字段精要）
| 字段 | 填写 |
|---|---|
| 发生时间｜事项对象｜谁触发 | |
| 实际输入及来源｜处理步骤｜用了什么系统/表格 | |
| 哪步需人工判断｜出现什么异常/返工 | |
| 最终谁决定｜结果记录在哪｜如何判断处理正确 | |
| 当前耗时与人数｜错误/延误后果 | |

## C 问题结构（12 判断项，每项记「事实/证据位置/待确认」）
发生频率｜业务规模｜人工工作量｜错误类型｜可核验结果｜业务负责人｜使用者｜风险负责人｜数据与权限｜系统接入｜系统能否承载结果｜历史样本与结论

## D AI 必要性初判（8 问，每问「回答/依据」）
现有配置能解决吗｜固定规则能解决吗｜报表能解决吗｜需理解非结构化材料吗｜需在不完整信息下建议吗｜需动态选步骤吗｜错误可发现可撤销吗｜结果进业务前谁确认

## E 候选任务单元（每任务一卡）
名称｜触发｜输入｜处理｜输出｜使用者｜负责人｜最终结果｜完成判据｜人工确认点｜首期排除｜待补证据

## F 调查结论（五选一）
进入场景比较 / 退回补充 / 缩小后再查 / 暂停 / 终止 ＋ 理由＋缺材料＋反对意见＋决定人＋日期＋下一步责任人

**完成标准（10 条精要）**：原文可追溯；≥1 真实事项；负责人与操作人员参与；正常+异常路径都有；数据权限经核验非「应该可以」；≥1 边界明确候选单元；缺口具体到文件/样本/人。
**Hold**：无真实事项／无业务结果确认人／用未测指标作准入依据／把「想用 AI」当必要性证明。
