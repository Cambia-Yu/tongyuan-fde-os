# TOOL-009｜受控部署记录表（Controlled Deployment Sheet）草案

> **白话**：系统过了考试（GATE-5）不等于能撒手放进真实业务。本表回答一个问题：**带着哪些权限、人工控制、监测和停止恢复机制，可以在多大范围进入真实环境**（服务 GATE-6）。四种运行方式是**可选择的控制模式，不是必须爬的梯子**——每个项目先按风险选目标模式，允许长期停在辅助或守卫，也允许跳过或退回。

## 四种运行方式（控制模式；非升级阶梯）
| 模式 | AI 能看 | AI 能建议 | AI 能执行 | 贯穿案例示例（支付前审核） |
|---|---|---|---|---|
| 影子 | 真实输入 | 并行结论（不进流程） | 无 | 审核全量人工做，AI 并行出预审结论比对 |
| 辅助 | 真实输入 | 建议+证据组织 | 无 | AI 预填审核要素，人逐项确认 |
| 守卫 | 真实输入 | 结论+放行建议 | **低风险动作**（白名单+限额） | 低风险单自动预审通过；高风险仅建议 |
| 全自动 | 真实输入 | — | 全部授权动作 | 全量自动审（仅当证据充分，非必然终点） |

**每模式必须写清四件事**：①谁批准进入（建议权/确认权/批准权按决策权矩阵）；②谁可请求暂停（任何人）、谁有实际停止/恢复权（批准人/原审批角色）；③进入证据（GATE-5 结论+本级权限表）、持续监测项、退出/降级触发（如守卫模式误放行率超项目阈值→降回辅助）；④对真实业务动作的权限边界——**高风险动作（付款放行/合同责任/不可逆处置）最终放行权永远在客户原有审批角色，不因模式升级而转移法定或组织责任**。

**模式与 U 状态不混写**：纯影子运行最多证明 U3；只有真实用户用结果完成真实任务并留痕才可能形成 U4（链路表 §7）。

## Entry Criteria（含 U2 上线准备六项——任一缺位即未达 U2）
- GATE-5 通过（评测达标，TOOL-008 结论）；
- **目标模式已选定并有批准记录**（依据：动作风险/可逆性/审批责任/证据质量——不预设「越自动越好」；**含影子模式**——影子同样读取真实输入，未经模式批准与数据授权不得进入真实环境）；
- **U2 六项书面就位**：①权限表与停止/恢复责任人；②真实数据使用/最小化/保留授权；③鉴权与访问控制；④日志、审计与事件追踪；⑤安全/隐私检查；⑥维护、值守、支持与变更责任。

## Actions
1. **选式**：按四要素选目标模式（**归属：动作风险/可逆性/审批责任=业务侧确认；证据质量=技术方评估**——填错归属即越权），登记理由与批准人（允许跳过不适用模式、允许长期停级、允许降级）；
2. **配权**：权限白名单/限额逐项登记（守卫模式尤其：可执行动作清单+金额/数量上限）；
3. **设监测**：按 NIST Manage 4.1——性能监测+用户反馈捕获+申诉/覆盖记录；**对抗/欺诈风险（故意伪造输入骗过系统）登记为监测项候选**（当前无专门机制=已知缺口，不得假装已覆盖）；变更管理（模型/Skill 版本变更走 DEC-015 路由）；
4. **渐进样本**（瓴羊式低谷→高峰→渐扩**仅作单组织参照**，非必经路径）：无论何种节奏，每扩大一批都按 TOOL-007 采集并核对——**误放行=应拦截未拦截（错误通过）；漏放行/错拦截=应放行被拦（错误拒绝）**，分向统计（方向配反=回滚触发配置错误）；影子模式下「扩大」仅指并行比对覆盖面；
5. **回滚预案与演练分档**：填写十要素，并按风险选定演练档位（批准记录留档）——**①文档检查**（十要素齐备）；**②桌面推演**（发现缺口用）；**③代表性环境技术回退+人工接管演练**。**仅①②不得写成「已验证恢复能力」**；守卫/全自动模式按项目风险决定是否强制③。

## 回滚十要素（回滚≠把代码退回上一版；**安全关键项未知=直接 Hold**，见 Hold 条件）
| 要素 | 要求 |
|---|---|
| 触发条件 | 量化/事件式（如误放行率超阈、单笔重大错误、客户叫停） |
| 影响范围 | 在途任务/已出结果/受影响用户清单 |
| 实际停止授权 | 谁在多长时间内有权停（预授权，不必临时请示） |
| 技术降级动作 | 切回辅助/影子或下线通道的具体操作 |
| 人工/原流程接管 | 谁接、怎么接、容量是否够 |
| 已生成结果隔离与纠正 | 存疑输出标记/复检/客户沟通 |
| 数据与审计保全 | 事件前后数据封存、日志保全（复用 TOOL-007 边界） |
| 人员通知 | 客户侧/内部/受影响用户（NIST Manage 4.3） |
| 恢复验证 | 修复后须过回归集（TOOL-008）+本轮触发条件的专项复测 |
| 重新上线条件 | 谁批准、依据什么证据（可能低于/高于原条件） |

组织责任归属或恢复时限无法确定的写**未知**，不补造。

## Exit Criteria
- GATE-6 结论（**六态就地定义：通过／有条件通过／退回补充／缩小范围／暂停／终止**）：生产风险是否可接受；**结论签发**＝公司有权人（决策权矩阵「阶段放行」行；矩阵见组织模型 v0.1.1 §3）——**只判断风险，不构成部署认证、更不等于 U4/U5**；
- 权限表/监测项/回滚十要素三件齐备且有批准记录。

## Hold 条件（Unknown 分两类——「标未知」不得绕过安全项）
- **安全关键未知 → 直接 Hold（含影子模式）**：真实环境数据授权／实际停止权／技术停用降级路径／人工与原流程接管责任及容量／日志与审计可得性／恢复与重上线批准权——任一未知即停，不因「已登记 Unknown」放行；
- **可带风险接受的未知**：跨组织通用恢复时限、非关键通知 SLA 等——须登记**风险接受人**与**临时补偿控制**；
- 高风险动作无人工确认点 → 停（R-C05 系）；
- 目标模式选择无批准记录 → 停在**影子之前**（不得进入真实环境）；
- 触发回滚后未完成恢复验证 → 不得重新上线（恢复验证=回归集通过 **+** 在途任务处置核对 + 人工接管容量核对 + 监测告警恢复确认——不只测模型能力）。


## 附｜贯穿案例最小填写示例（承 TOOL-008 示例，GATE-5 有条件通过后；**纸面推演，不是现场证据**）
- **选式**：审核错误后果=错放行付款（不可逆、资金风险）→ 目标模式=**守卫**（低风险单自动预审+限额，高风险仅建议）；批准=公司有权人（依据决策权矩阵）；**不选全自动**且这是合法终点；
- **行业读者确认**：哪些单属「低风险」（金额上限/单据类型）、误放行率的项目阈值（业务口径）；
- **工程读者实现**：权限白名单+限额、监测项（误放行/漏放行/申诉覆盖）、日志审计、回滚十要素；**守卫模式须档位③演练**（资金风险）——当前仅能做桌面推演=**登记「恢复能力未验证」**；
- **触发示例**：误放行率超阈→预授权停止人（客户原审批角色+技术交付负责人）执行降级至辅助→在途单复检→回归集+触发条件专项复测→有权人批准重上；
- **回流**：本阶段 TOOL-007 采集的使用/绕过/申诉记录→按 DEL-011 路由进候选池；
- **谁不能替谁**：行业读者不批准权限与演练档位；工程读者不定义风险等级与阈值；停止权与重上批准=预授权清单指定人；
- **U 状态**：守卫模式运行+影子比对≠U4；获授权审核员用系统结论真实放行并留痕 → 首条 U4 证据。
