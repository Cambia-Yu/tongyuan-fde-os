# TOOL-007｜使用轨迹表（Usage Trace Sheet）草案

## Purpose｜为什么存在
系统上线（U3 受控上线）只是开始。本表记录**部署后**获授权真实用户与系统的真实互动——用了什么、改了什么、绕过了什么、求助了什么、业务结果如何——产出四样东西：五级使用状态的判定事实（U4/U5）、评测集的候选案例（经四步入库路由）、阶段 08 产品决定（终止/缩小/迭代/扩大）的依据、上浮候选评审（08→09）的重复模式证据。

**三条铁律**：一次轨迹≠使用率；一次使用≠现场验证；原始轨迹≠评测集。

## Entry Criteria｜进入条件
- 系统已达 **U3 受控上线**：获授权真实用户，通过客户实际允许的交付入口（URL/ERP 内嵌/工作台/API/批处理/审批流/桌面工具——URL 合法但「有 URL」≠已交付），在真实工作环境完成真实业务任务并留痕；
- 数据授权完成：采集范围、脱敏规则、访问控制、保留期限四项经客户书面确认；
- 观察者/审核者角色已指定（技术交付负责人+客户业务教练候选）。

## Actions｜怎么做
1. **定义采集层**：系统侧（可审计的输入/输出/工具动作/异常——**不记录模型隐藏思维链**）+人工侧（接受/修改/拒绝/覆盖/绕过/求助/升级七类行为）+结果侧（最终业务动作与结果，标注与 TOOL-004 基线的可比口径）。
2. **逐事件记录**（人机一次完整任务交互=一条轨迹）：字段见下表。
3. **三列分立**：观察事实（系统日志/界面记录）、用户自述（事后访谈）、审核者推断——不得混写。
4. **周期归并**：按周/月归并为使用率与模式统计（单条轨迹只作案例，不作率）。
5. **路由出口**：每条轨迹标注去向——评测候选（走四步入库：识别→脱敏→专家判定→版本化）/产品决定输入/上浮候选评审/仅存档。

## Exit Criteria
- U4 判定所需最小事实存在：真实任务+可追溯记录；
- U5 判定（如申请）有重复、具代表性的使用与结果证据集；
- 采集边界（授权/脱敏/保留期）被执行并有审计痕迹。

## Artifacts / Fields
| 字段 | 填写要求 |
|---|---|
| 轨迹编号/时间 | 人机一次完整任务交互 |
| 用户角色/授权依据 | 获授权用户（脱敏标识） |
| 真实任务 | 业务事项（对照任务单元） |
| 入口类型与系统位置 | URL/内嵌/工作台/API/批处理/审批流/桌面工具+实际系统 |
| 系统输入/输出 | 可审计记录；**不含模型隐藏思维链** |
| 工具动作/异常 | 调用链与异常类型 |
| 人工行为七类 | 接受/修改/拒绝/覆盖/绕过/求助/升级（七选多+说明） |
| 最终业务动作与结果 | 与基线可比口径标注 |
| 版本 | 模型/Skill/工作流版本 |
| 观察事实/用户自述/审核者推断 | 三列分立，不得混写 |
| 数据边界 | 授权范围/脱敏/访问控制/保留期 |
| 路由出口 | 评测候选/产品决定/上浮候选/存档 |

## Hold 条件
- 采集未经客户书面授权 → 停采，仅保留系统自身运行日志；
- 无法区分人工行为类别（日志粒度不足）→ 降级为「结果对照」模式，不记行为层；
- 单条轨迹被直接当使用率/评测集使用 → 违反三铁律，退回；
- 轨迹含未脱敏敏感数据 → 立即隔离该条，走脱敏补救后重评。
