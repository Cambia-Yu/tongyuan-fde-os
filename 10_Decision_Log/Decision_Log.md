## DEC-2026-002｜FDE OS 根目录位置

- **决定**：建在 `/Users/cambia/Documents/notes/Tongyuan-FDE-OS/`。

## DEC-2026-003｜《FDE手册编写与现场验证规范》V0.2 的宪法地位

- **决定**：手册规范 V0.2 是 03_Delivery_Playbook 与 05_Field_Toolkit 的编写与验证宪法，FDE OS **不重写、不覆盖、不迁移**该文件；ForFlow「FDE手册第一版」工作台原位保留，Master Index 以挂链方式接入。
- **理由**：该规范已内建证据等级、成熟七态、四层验证、四张控制台账——重写等于推倒已有成熟资产；任务书 §18 硬规则禁止修改原文件。
- **发现的版本问题**：ForFlow README 引用的规范路径是 home 目录 V0.1（2026-07-23），而最新版是 Downloads 的 V0.2（2026-07-24）——存在版本漂移，待手册工作恢复时同步（本系统不代改）。
- **重审条件**：手册规范升级到 V0.3+ 时，重新确认宪法条款引用。

## DEC-2026-004｜「湖南 FDE」报告标记为外部样本并隔离

- **决定**：`FDE模式AI转型可行性分析.md`（Scribd 第三方报告）标记为 **EXT 外部样本**，不进入 FDE OS 主线证据链。

- **重审条件**：无。

## DEC-2026-007｜三层状态词汇制

- **决定**：FDE OS 同时使用三套状态词汇并严格区分（见 IA §4）：知识状态（FACT/OBSERVATION/INFERENCE/DESIGN DECISION/HYPOTHESIS，给主张用）、证据等级（L1-L5，给来源用）、成熟状态（草拟→稳定做法七态，给规则/工具/资产用，继承手册规范 §5.2）。
- **理由**：任务书 §13/§14 与手册规范 §5 各自定义了一套体系且都在用；不合并（各有语义），只做映射，防止「设计决定写成事实」。
- **重审条件**：实际使用中发现三套词汇被混用时修订映射表。

## DEC-2026-008｜编号双轨制

- **决定**：手册作业包/资产继续用其原有「〔作业-XX-NN〕」「〔资产-XX-NN〕」编号；FDE OS 新设 TOOL-NNN 仅作 OS 内二级索引；映射表维护在 Master Index。

- **重审条件**：无。

## DEC-2026-009｜十阶段链保持「假设」地位

- **决定**：任务书 §3 的十阶段链在 Master Index 中标 HYPOTHESIS，不因「已经讨论过」而默认正确；现有 L0-L5 准入层级映射为 GATE-0 区间的实现件。
- **理由**：任务书 §3 明确要求用公开证据重检（线性假设、并行、回退、Gate 化）；且本地审计发现该链与手册规范 8 章结构存在两处已知错位（Baseline 阶段缺位、客户采用/ROI 阶段缺位，见 Gap Map G-03/G-05）。
- **重审条件**：Phase 5 定向研究完成后。
